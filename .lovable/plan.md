

# Audit: Cause-Effect Insight Not Visible in "How You Show Up"

## Root Cause (confirmed via code trace)

The cause-effect insight IS being generated by Path E in the edge function, but it is **intentionally nullified before reaching the UI**. Here's the exact chain:

1. **Edge function line 626-628**: When `causeEffectInsight` exists and `presenceActions.length < 3`, it gets pushed into `presenceActions[]`
2. **Edge function line 637**: The response then sets `causeEffectInsight` to `null` because it was inlined into `presenceActions`:
   ```
   causeEffectInsight: causeEffectInsight && presenceActions.includes(causeEffectInsight) ? null : causeEffectInsight
   ```
3. **UI line 531**: The standalone cause-effect section checks `data.causeEffectInsight` — which is now `null` — so it never renders
4. **UI line 485**: The `presenceActions` array (which contains the cause-effect text) only renders inside the "How You Show Up" card, which is gated by `data.presenceLabel`. If this card renders, the cause-effect appears as a small bullet — easily missed. If it doesn't render, the insight is completely invisible.

**In summary**: A previous fix to "inline" cause-effect into the presence card created a situation where the insight is either buried in a bullet list or completely hidden.

## Secondary Issue: presenceLabel reliability

For a user without high-stakes calendar events, coach presence keywords, or readiness scores, the presence score defaults to only `baselinePts` (max 15). The label "Building your presence pattern" is assigned at score < 30, so the section DOES render — but the cause-effect is buried as a bullet item under it, not a prominent insight.

## Fix

### File 1: `supabase/functions/performance-rhythm-insights/index.ts`

**Stop nullifying causeEffectInsight**. Remove the conditional null on line 637 — always return the raw `causeEffectInsight` value. The UI will decide where to render it.

```
// Line 637: change from
causeEffectInsight: causeEffectInsight && presenceActions.includes(causeEffectInsight) ? null : causeEffectInsight,
// to
causeEffectInsight,
```

**Also**: Remove the injection into `presenceActions` (lines 625-628) to avoid duplication. The cause-effect should render as its own prominent section, not as a bullet.

### File 2: `src/components/insights/PerformanceRhythmCard.tsx`

**Make the standalone cause-effect section render independently** of whether it also appears in presenceActions. The existing UI block at line 530-535 already handles this — it just needs `data.causeEffectInsight` to not be null.

No other UI changes needed — the existing rendering code is correct.

## Summary

|--------|------|------|
| Stop nullifying causeEffectInsight | `performance-rhythm-insights/index.ts` | Remove conditional null + remove presenceActions injection |
| No UI change needed | `PerformanceRhythmCard.tsx` | Existing standalone block at line 530 will render once data flows |

One edge function redeploy. No DB changes.
